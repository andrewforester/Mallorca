# Arena viewer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Save every arena run in a shared directory and browse the runs and their hands in a local web page.

**Architecture:** The CLI writes reports and JSONL hands to `resultsDir()`. A second Vite app under
`web/tools/arena/ui` serves the directory through a dev-server plugin; a Web Worker parses the hands and pure
functions compute the curve, slices and hand list rendered by Preact components.

**Tech Stack:** Node 24, TypeScript strict, Vite 8, Preact 11, Vitest 5 with happy-dom and Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-30-arena-ui-design.md`

## Global Constraints

- No comments in code or config. No `eslint-disable`, no loosened tests.
- Non-test files: at most 400 lines, 60 lines per function, nesting 3, complexity 12, 4 parameters.
- UI copy: no all-caps words, no em or en dashes as punctuation.
- Viewer imports from `src` only `game/records/pokerstars.ts`, `game/records/record.ts` and engine types.
- Before every commit: `npm run lint`, `npx tsc --noEmit`, `npm test` from `web/`.

## Review Focus

- A hands file truncated mid-line (run killed while writing): the worker skips the broken line and reports the count.
- A report whose hands file is missing: the run is listed, the hand sections say there are no hands.
- An empty results directory or a directory that does not exist: the list says there are no runs yet.
- A request for `../package.json` or `a/b.jsonl` to `/api/hands`: 404.
- A run of a bot against itself (`math` vs `math`): A is decided by hand number, not by name.

### Task 4: Analysis

**Files:** Create `web/tools/arena/ui/analysis.ts`, `analysis.test.ts`.

**Interfaces — Produces:**
- `interface HandSummary { line: number; handNumber: number; pair: number; aSeat: 0 | 1; position: 'button' | 'bigBlind'; aNet: number; street: 'preflop' | 'flop' | 'turn' | 'river'; showdown: boolean; pot: number }`
- `summarize(record: HandRecord, line: number): HandSummary`

- `interface Slice { key: string; hands: number; bb: number; bbPer100: number }`;
  `slices(hands, bigBlind): { position: Slice[]; street: Slice[]; showdown: Slice[] }`
- `interface HandFilter { position?: …; street?: …; showdown?: boolean }`;
  `pairRows(hands, filter, sort: 'net' | 'pot'): PairRow[]` with `PairRow { pair: number; net: number; pot: number; hands: [HandSummary, HandSummary] }`, sorted descending by `|net|` or by max pot, a pair kept when either hand passes the filter.

- [ ] Tests on records built by `playPair` + `handRecord` (always-call vs always-raise, seed 4, 8 pairs) and by
  math vs math: `pairNets` equals `playPair(...).net`; mean bb/100 equals `summarize` of `stats.ts`;
  positions split evenly; slice totals add up to the total; `cumulative` length ≤ 600 and its last point is the

- [ ] Implement, commit `feat(arena): viewer analysis`.
